# iac

Terraform infrastructure-as-code for multiple cloud providers. Machine
configuration management lives in the separate `ansible` repo; this repo
provisions cloud infrastructure.

See [CLAUDE.md](CLAUDE.md) for the conventions used when adding new environments
and infrastructure.

## Layout

```
modules/                          Reusable Terraform modules (<provider>-<thing>)
  do-wireguard/                   WireGuard VPN droplet + DO Project, via cloud-init
environments/                     Root configs you run (terraform apply)
  do/                             DigitalOcean
    vpn/                          Cheap WireGuard VPN (its own DO Project)
  gcp/                            Google Cloud (empty for now)
scripts/
  vpn.sh                          Mac helper to connect/disconnect (wg-quick)
```

Each `environments/<provider>/<project>/` directory is an independent Terraform
root with its own local state. Provider dirs use short slugs: `do`, `gcp`, `aws`.

## Make targets

A `Makefile` drives Terraform per environment. Select an environment with
`env=<name>` (a path under `environments/`, or a short alias) and run one or
more `tf-*` targets:

```bash
make tf-init tf-plan tf-apply env=do/vpn   # full path
make tf-apply env=vpn                       # 'vpn' is an alias for do/vpn
make tf-destroy env=do/vpn
make tf-plan env=do/vpn ARGS="-target=module.vpn"
make list-envs                              # list environments + aliases
make help
```

Add aliases by editing the `ALIAS_<name>` lines in the `Makefile`.

## Prerequisites

```bash
brew install terraform wireguard-tools
```

- A DigitalOcean account and API token (Control Panel -> API -> Tokens).
- An SSH key (default expected at `~/.ssh/id_ed25519.pub`).

## DigitalOcean WireGuard VPN

Stands up the cheapest DigitalOcean droplet (~$4/mo) inside its own DigitalOcean
**Project** (so the VPN infra is isolated from everything else), installs and
configures WireGuard via cloud-init, opens the firewall, and generates a
ready-to-use client config for this Mac.

### 1. Configure

```bash
cd environments/do/vpn
cp terraform.tfvars.example terraform.tfvars   # edit region, etc.
export DIGITALOCEAN_TOKEN=dop_v1_xxxxxxxx       # your DO API token
```

### 2. Provision

```bash
terraform init
terraform apply
```

Terraform writes the client config to
`environments/do/vpn/generated/wireguard-client.conf` (gitignored; it contains a
private key).

### 3. Connect from the Mac

Either import the generated `.conf` into the **WireGuard** app (App Store) and
toggle it on/off, or use the helper script:

```bash
# from the repo root
./scripts/vpn.sh up       # connect
./scripts/vpn.sh status   # check
./scripts/vpn.sh down     # disconnect
```

Verify your traffic exits via the droplet:

```bash
curl ifconfig.me   # should print the VPN endpoint IP when connected
```

### 4. Tear down (stop paying)

```bash
cd environments/do/vpn
terraform destroy
```

`apply` to spin it up when you want a VPN, `destroy` when you're done.

## Notes / security

- WireGuard server and client keys are generated by the `OJFord/wireguard`
  provider and stored in Terraform **state**. Keep state and the generated
  `.conf` private (both are gitignored).
- The default config is a **full tunnel** (`AllowedIPs = 0.0.0.0/0, ::/0`), so
  all Mac traffic routes through the droplet. Adjust `client_allowed_ips` in the
  module for split tunneling.
- For tighter security, set `ssh_allowed_cidrs` to your current public IP.
